# 操作手冊

**這份是「怎麼做」。** 想理解「為什麼這樣設計」，看 [`README.md`](README.md)。

---

## 一、導入

### 開新專案

```bash
cp -r <樣板路徑>/docs ./docs
cp <樣板路徑>/CLAUDE.md.example ./CLAUDE.md
```

接著只填 `CLAUDE.md` 的**三段**：技術棧、指令、禁區。其餘留空（理由見下方第四節）。

十行就夠：

```markdown
# 專案守則

## 技術棧
Python 3.12 / FastAPI / SQLite

## 指令
pytest              # 測試
ruff check .        # lint

## 禁區
- 不得新增套件，要加先問
- data/ 底下是原始資料，唯讀
```

### 既有專案導入

把這段交給 AI：

```
讀一下這個專案的結構和依賴設定檔，
幫我填 CLAUDE.md 的「技術棧」和「指令」兩段。
「禁區」的部分列出你的建議，我來確認。
```

> **禁區必須由人確認。** 哪裡碰不得，只有專案的人知道。

## 二、日常循環

每個功能跑一輪：

```
① 想做一個功能
      │
      ├─ 要說服別人？或三個月後會忘記為什麼這樣定？
      │     是 ─▶ 先寫 PRD（docs/prd/_template.md）
      │     否 ─▶ 直接下一步
      ▼
② 寫 SPEC（docs/spec/_template.md）
   ★ 沒有可執行的 Acceptance Criteria，就不要往下走
      ▼
③ 叫 AI 照 SPEC 實作
      ▼
④ 跑 AC 表格裡的測試
      ▼
⑤ 過了才算完 ── 沒過就回到 ③
      ▼
⑥ 回頭看 PRD：原本的問題真的解決了嗎？
```

## 三、常用指令範本

### 起草 SPEC（不要自己從零寫）

```
我要做一個「<功能名稱>」功能。
用 docs/spec/_template.md 的格式幫我起草 SPEC。

- 不確定的地方列在「待確認」，不要自己假設
- Acceptance Criteria 要寫成可執行的 Given/When/Then
- 邊界情況那節請盡量列，尤其是空資料、逾時、權限不足
```

AI 起草、人審定。這比對著空白 template 發呆快得多，而且它會逼你面對你沒想過的邊界情況。

### 實作

```
照 docs/spec/<編號>-<名稱>.md 實作。
SPEC 沒定義到的情況停下來問，不要自己決定。
```

### 其他四個時機

| 什麼時候 | 說這句 |
|---|---|
| AI 犯了一個會重複發生的錯 | 「把這個加進 CLAUDE.md 的已知地雷，寫清楚為什麼」 |
| 做了以後會被質疑的技術選擇 | 「用 docs/adr/_template.md 補一份 ADR，被否決的方案也要寫」 |
| 功能太大，一次做不完 | 「把這份 SPEC 切成 PLAN.md，標出任務依賴」 |
| 架構有變動 | 「更新 docs/ARCHITECTURE.md」 |

## 四、哪些現在寫、哪些等

不是所有文件都該在第一天產出。**寫太早的文件是猜測，而 AI 會把猜測當指令執行。**

### `CLAUDE.md`

| 段落 | 什麼時候寫 | 為什麼 |
|---|---|---|
| 技術棧 | **第一天** | 已經是事實 |
| 指令 | **第一天** | 已經是事實，且缺了 AI 無法自我驗證 |
| 禁區 | **第一天** | 缺了會立刻出事 |
| 程式碼慣例 | 第一次覺得「風格不對」時 | 提前寫是憑空想像 |
| 已知地雷 | 踩到才寫 | 提前寫**一定**是編的 |

### `ARCHITECTURE.md`

**不要第一天寫。**

程式碼還不存在時畫的架構圖，畫的是「希望的樣子」，但 AI 會當成事實去執行。結果是照著猜的架構蓋到一半發現不合用，文件從此跟程式碼不一致——變成一份騙人的文件。

**等到出現這兩個徵兆再寫**，那時候寫的是「現況」，而現況可以驗證：

- AI 開始把檔案放錯位置
- AI 重複寫了已經存在的功能

### `PRD` / `ADR`

這兩份反而要**當下就寫**，因為它們記錄的也是事實：PRD 記錄「當時的問題」，ADR 記錄「當時的限制與選擇」。

事後補寫的 ADR 幾乎都是假的——人會不自覺地把結果合理化，忘掉當初真正的猶豫。

## 五、一個判準貫穿全部

每次猶豫「這份文件現在該不該寫」，問這一句：

> ### 它描述的是**已經存在的事實**，還是**我希望的樣子**？

- **事實** → 可以寫
- **希望** → 寫了就是猜測，而 AI 會把猜測當指令執行

技術棧、指令、遇到的問題、當下的限制 → 都是事實。
架構、慣例、還沒發生的地雷 → 都是希望。
