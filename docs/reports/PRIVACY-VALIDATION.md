## 實際驗證範圍

- 真實 Git 提交與本機遠端推送：乾淨內容可通過；檔案、提交訊息或舊提交含私人路徑時被阻擋，受阻擋的分支未出現在測試遠端。測試只使用 `.sandbox/` 內的臨時倉庫，沒有推送至 GitHub。
- 工作目錄與暫存內容不同時，以實際暫存內容為準；同一 Git blob 在歷史中曾放入私人目錄、含空白檔名或標籤文字，也會檢查。
- 常見 Windows、JSON、URL 編碼及 Unicode 路徑辨識；正常網址不誤判；強制加入本機設定、二進位未審查、超大物件與無效例外檔會阻擋。
- 精確內容雜湊的審查例外只適用原檔內容，變更後失效；未暫存的例外不放行提交；既有 hooks 與自訂 hooks 路徑不被覆蓋。
- 真正執行 Node／Python 測試及 OpenSpec 封存；新公開日誌雜湊對應去識別化後的位元組，本機保留原始日誌；改變本機設定後舊證據失效；Git 換行轉換不破壞公開日誌雜湊。
- 接入型與平面型 hook 入口、導入的忽略規則與 `.gitattributes` 原內容保留／復原。

## 使用限制

hooks 必須在每個 clone 啟用；可被繞過，也不涵蓋網站直接上傳。此工具辨識私人路徑，不是完整的秘密掃描器。未辨識的路徑或編碼不能保證攔截；非文字檔案需人工審查，Git LFS／submodule 與過大歷史不在自動檢查支援範圍。既有專案需另外審查升級，不會因模板更新而自動取得功能。

操作見 [路徑隱私保護](../../starter/PRIVACY.md)，本次程式與測試檔案雜湊見 [驗證來源快照](privacy-validation-inputs.json)。
