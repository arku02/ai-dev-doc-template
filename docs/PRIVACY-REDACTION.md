# 歷史證據的去識別化與公開

歷史保留的目的是保存真實需求、決策及驗證結果，不是要求公開個人電腦資訊。封存文件可以為隱私目的去識別化，但必須說明修改範圍，不能把修改後的副本當成未改動的原始證據。

目前模板已加入新證據的路徑去識別化、本機設定覆寫，以及可啟用的 Git 提交／推送前檢查，見 [開發期間的路徑隱私保護](../starter/PRIVACY.md)。下文處理的是既有歷史資料；新工具不會自動遷移或改寫它們。

## 規則適用範圍

新專案的規則已納入 [starter/PROJECT-RULES.md](../starter/PROJECT-RULES.md)；通用導入會將它複製為 `.integration/PROJECT-RULES.md`。既有專案不會自動更新，應將其中「歷史證據與隱私」段落合併到實際使用的規則檔，並將其他位置「不得重寫歷史封存證據」等絕對禁令改為：

> 不得竄改歷史事實、測試結果或決策。允許有紀錄的隱私去識別化；公開副本須標明處理範圍及原始證據的驗證限制，不得用去識別化掩蓋失敗或補造通過證據。

保留既有產品規則，不以整份覆蓋方式升級。這是文件維護，不需要虛構產品行為差異以通過 OpenSpec 的功能流程。

## 路徑如何表示

| 位置 | 建議表示 |
|---|---|
| 文件中的程式或測試位置 | `src/main.py`、`tests/test_feature.py` 等專案相對路徑 |
| 敘述中必須表達專案根目錄 | `<PROJECT_ROOT>/tests/test_feature.py` |
| 敘述中的家目錄或外部工具位置 | `<HOME>`、`<PYTHON_EXECUTABLE>` 等不含個人資訊的標記 |
| `workflow.config.json` 的 Python 命令 | `python` 或實際存在的 `.venv/Scripts/python.exe`／`.venv/bin/python` |
| 原始測試日誌與回溯 | 可能仍含絕對路徑；公開前另行檢查，不假設已自動清理 |

佔位標記只用於敘述或明確標示的公開證據副本，不能直接塞進執行設定。

## 既有專案的處理步驟

1. 合併上面的規則，盤點預計公開的檔案，包括封存 Markdown、`.workflow/evidence/`、`.workflow/receipts/`、測試日誌、環境診斷報告與導入紀錄。也檢查 Windows 反斜線、JSON 跳脫、正斜線與 `file:` URL 等路徑形式。
2. 如需保留原始證據，先放到不隨公開倉庫、壓縮檔或發佈附件提供的受控位置。公開版本保留相同相對位置的去識別化副本或明確標示的摘要；若不公開某份原始檔，修正引用並註明無法獨立核對的部分。
3. 僅替換辨識資訊，不更改需求內容、通過／失敗、案例數、執行時間或決策結論。對 JSON 等機器格式維持可解析性，使用相鄰說明檔標示副本性質，避免插入非法註解。
4. 在專案的 `docs/privacy-redactions.md` 記錄日期、原因、影響檔案的相對路徑、替換類別、原始資料是否另存，以及驗證限制。不要在「修改前／修改後」對照、備份位置或整理紀錄中再次寫出私人路徑。
5. 檢查雜湊與證據關係。此版本會對原始日誌計算 `logHash`，並用 `digest` 檢查輸入；改動日誌或設定後不能宣稱舊證據仍適用。活動變更重新 verify；已封存副本保留原紀錄並註明哪些雜湊不再對應公開內容。不要手改雜湊、重開已封存變更或回填新測試為舊結果。若另計公開副本雜湊，將其記在整理紀錄，明列為副本完整性用途。
6. 檢查待公開檔案、版本差異及準備推送的 Git 歷史；公開範圍也包含附帶的日誌、備份與附件。必要時重新執行現有測試，結果記為本次檢查，不冒充歷史驗證。

`.workflow/imports/` 的 manifest 保存目標絕對路徑、內容雜湊與復原資料，是本機操作資料；需要復原時保留原檔於私有位置，不直接修改其 `target` 或 `digest` 再拿去 rollback。新版導入會將該目錄排除版控，攔截器也會阻擋強制加入的原檔。工具沒有自動整理舊證據或改寫 Git 歷史的功能。

## Git 歷史與公開邊界

`.gitignore` 只避免未追蹤檔案被一般加入流程納入，不會清除已追蹤檔案或舊提交中的內容。即使尚未推送，私人路徑若已在本機提交內，推送那些提交仍可能一併公開。

若必須保留現有 Git 歷史，需另行規劃歷史清理與協作者同步；不要把它視為一般文件替換。若不需要公開開發歷史，可從檢查過的乾淨內容建立獨立公開倉庫，私有原倉庫保留追溯。已對外公開的資訊不能只靠新的修改提交收回，也不能保證其他人的副本同步消失。

## 整理紀錄範例

以下只是格式，不代表任何專案已完成去識別化：

```text
日期：YYYY-MM-DD
原因：公開前移除個人環境資訊
範圍：.workflow/evidence/<change>.json、.workflow/evidence/<change>.log
處理：將個人專案根路徑替換為 <PROJECT_ROOT>
性質：公開去識別化副本；保留歷史測試結果及原執行時間
原始資料：另存於受控位置，不隨公開版本提供
限制：原 logHash 不對應此公開日誌；無法只靠公開副本核對原始位元組
本次檢查：填入實際檢查與結果；未執行的檢查明列未執行
```
